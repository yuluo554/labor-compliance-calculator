## 五、方法论提醒（这个仓库特有的坑）

- **`--preview` 是"门控命中专用"还是"任意坐标通用"必须先拍板**：现有实现是后者、文档是前者；测试只覆盖前者。改任一方向都要同步 `plan/03:131`、`plan/04:346,362`、README 第 111 行、`tech report:311` 四处。
- **`allow_pending=True` 路径禁止产出金额**：`pipeline.py:141-144` 的提前 return 是这条纪律的实现；改 preview 语义时不要把已核对坐标也带进 `allow_pending`（否则等于绕过门控）。
- **PIL/lxml 是 openpyxl 的传递依赖**：`PySide6` 与 `openpyxl.drawing.image` 都会拉 PIL。excludes 加 `PIL`/`lxml` 后**必须实测 XLSX 导出仍成功**（本次已实测通过：rc 0、14,008 B）。
- **`PYZ-00.toc` 才是"内嵌了哪些包"的真凭据**：zip 顶层没有 `openpyxl/` 不代表没内嵌；判断依赖是否入包要查 PYZ toc 或跑功能，不要只看目录。
- **打包可复跑 ≠ exe 可复跑**：`release_assets.py pack` 固定时间戳使 zip 字节一致；PyInstaller 重建 exe 本身不保证字节一致（留档已区分）。
- **`py` 启动器绕过 venv**：所有 venv 段用 `python -m pip`；CI 与 README 都是这么写的。
- **3.8 偶发退出期 segfault（139）**：若全量跑出 139 但测试结果全绿，按 README 的既定做法分批逐文件确认，不要当成用例失败。
- **`_backups/` 未忽略**：pack 默认写仓库根的 `_backups/release`，79 MB zip 会进 `git status`；本批先加 ignore。
- **干净环境**：用 `$TEMP/lcc-v011` 新 venv，不复用全局 py3.8/3.12；用完删除并确认 `git status` 只多 `update/`。
