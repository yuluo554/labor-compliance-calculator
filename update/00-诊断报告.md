## 三、做得好的部分（迭代中不要破坏）

1. **门控单点 + 类型级封堵**：`gate.EffectiveRuleset` 是唯一可计算规则集；引擎签名只接受它；`pending` 抛 `GateError`（exit 2）。
2. **坐标强约束**：跨地区/跨年度混用机制上报错；`pending` 坐标给出逐条路径清单。
3. **三态语义清楚**：`verified` / `pending` / 预览降级（exit 1），且预览不进入引擎、不输出金额。
4. **基准体系分层且非空验**：B1/B2 依赖真值库、B4/B5 纯规则驱动；每个套件都有"注入漂移必须失败"的阳性对照；`B4/B5 不读真值库` 有专门测试。
5. **零政策字面量门禁**扫描引擎/基准/前端（含 docstring），11 文件 0 命中。
6. **冻结数据纪律**：`gen_rulesets --check` / `gen_cases --check` 逐字节对账；CR/LF 守门。
7. **报告可复现**：Markdown 与 XLSX 同源渲染、XLSX zip 元数据归一化，两次导出 sha256 相同（我们独立复现）。
8. **附件打包可复跑**：固定时间戳 + 排序，两次 pack sha256 相同（我们独立复现）。
9. **中立目录 + 最小环境验收**：`verify_package.py` 剥 `PYTHONPATH`/`LCC_DATA_DIR`，跑 7 条断言（含 `--preview` 期望 1）。
10. **GUI 零判定逻辑**：AST 断言（不 import 引擎/参数库/门控、无算术、无政策数值）；offscreen 冒烟真实触发计算与导出。
11. **打包 datas 单一源**：`lcc.packaging.build_datas()`；两个 spec 都只调用它；`data/knowledge` 明确排除并有测试。
12. **脱敏工具入仓且三模式**：tracked / messages / history + 产物字节扫描；含阳性对照。
13. **发布留档完整**：`RELEASE-M6.md` / `HANDOFF-FINAL.md` 记录实测命令、sha256、CI run、复跑手册。

## 四、缺陷清单

### D1（P1）`--preview` 在已核对坐标上同样降级并打印"存在未核对项"的错误说明

**现象**
- **实测**：`py -3.12 -m lcc calc --preview examples/sample-case.json`（上海 2026，`规则包状态: [已核对]`）：
  - 输出 `规则包状态: [已核对]`，但只打印参数来源、**不输出任何金额**；
  - 结尾 `说明: 预览模式：参数条目存在未核对（pending）项，仅展示参数元信息，不输出任何金额结论。`
  - 退出码 **1**。
- **源码直读**：`code/src/lcc/pipeline.py:126-129` 只要 `request.preview` 为真就追加该 notice；`pipeline.py:141-144` 只要 `preview` 就 `return result`（不进入引擎）——与坐标状态无关。`pipeline.py:115` 传 `allow_pending=request.preview`。
- **文档口径**：README 第 111 行写「预览模式：**门控命中时**仅展示参数元信息」；`plan/03:131`、`plan/04:346,362` 都写「`--preview` 允许在**门控命中时**打印参数预览」、退出码 1 只对应「`--preview` **且门控命中**」。即文档假设"预览 = 门控命中时才降级"，实现是"只要带 `--preview` 就降级"。
- 测试只覆盖 pending 坐标（`test_cli_exit_codes.py:152`），已核对坐标的 preview 行为没有断言。

**影响**
- 用户对已核对坐标加 `--preview` 会得到"存在未核对项"的**错误说明**（实际没有 pending 项），并且看不到金额。
- 退出码表（plan/04 §八）与实现不一致：表里"`--preview` 且门控命中 → 1"，实际"`--preview` 任意坐标 → 1"。

**修复方向（见决策 D-1）**
- A：语义收窄为文档口径——`--preview` 在门控命中时才降级（已核对坐标正常出金额、exit 0）；notice 文案按实际状态分支。
- B：语义写实——保留"预览 = 只看参数"（任意坐标都降级），但把文档/退出码表改成"`--preview` → 1"，并修正 notice 文案（已核对时不说"存在 pending 项"）。
- 无论哪个，补一条"已核对坐标 + `--preview`"的测试。

### D2（P1）发布 GUI zip 含 PIL 10.7 MB / lxml 6.6 MB，打包白名单只管数据、不管依赖

**现象（实测）**
- Release `lcc-gui-0.1.0-win64.zip` 解压后 **140.3 MB / 1,125 条目**；其中 `PIL/` **6 个 .pyd、10.7 MB 未压缩 / 5.4 MB 压缩**，`lxml/` 16 条目 / 6.6 MB / 3.3 MB。
- CLI zip 同样带 `PIL/` 6 个 .pyd（10.7 MB）与 `lxml/`（38.4 MB 解压）。
- **来源（源码直读 + 构建产物）**：`PIL` 由 `PySide6` 与 `openpyxl.drawing.image` 拉进来；本机 `build/lcc-cli/xref-lcc-cli.html` 显示 `imported by: PySide6`、`openpyxl.drawing.graphic`、`openpyxl.drawing.image`。`lxml` 来自 openpyxl（`et_xmlfile`/`lxml`）。
- 两个 spec 的 `excludes` 只有 `["PySide6","tkinter","unittest","pydoc_data"]`（CLI）/ `["tkinter.test","unittest","pydoc_data"]`（GUI），**没有 `PIL`/`lxml`/`numpy`**。
- 反证：用 py3.12 + PyInstaller 6.22.3 在**未装 openpyxl**的临时副本构建 CLI → **21 MB / 30 文件**，无 `PIL`、无 `lxml`；selftest 通过。即这 17 MB 完全是 openpyxl 的可选依赖链带进来的。

**影响**
- CLI 版（用户只想命令行算金额）多带 17 MB 无用的图像/XML 库；GUI 同理。
- 打包"白名单"只覆盖 `data/`，依赖侧没有等价约束；红线扫描只查禁词，不查重依赖。

**修复方向**：两个 spec 的 `excludes` 增加 `"PIL"`、`"lxml"`（若 openpyxl 的 XLSX 写出不需要它们——需实测导出仍成功）；或把 `openpyxl` 从构建环境移除改用纯 stdlib XLSX writer（工作量大，见 D-3 选项）。加一条构建后断言：dist 内不得出现 `PIL/` 或 `lxml/`。

**现象**
- `code/pyproject.toml:30`：`build = ["pyinstaller>=5.13,<7"]`。
