## 一、痛点 → 能力转译表

| # | 现实痛点 | 典型错误 | 本项目能力 |
|---|---|---|---|
| P1 | N / N+1 / 2N 三口径混用 | 违法解除按 N 算、协商解除错加代通知金 | 解除情形 → 口径规则化判定（枚举 + 依据条款），判定与金额分离输出 |
| P2 | 三倍封顶与 12 年上限被忽略 | 月薪 8 万仍按实际工资全额算 | 封顶判定由**参数包**（当地社平工资 ×3）驱动，年限上限参数化，禁止硬编码 |
| P3 | 工作年限取整口径不清 | 满 6 个月不满 1 年被按半个月算 | 取整规则显式实现（满 6 个月不满 1 年 → 1 年；不满 6 个月 → 半个月）并进基准枚举 |
| P4 | 加班费倍数与工时制度错配 | 不定时工作制也给加班费、休息日按 300% | 工时制度门控 + 三档倍数（150/200/300%）+ 基数口径规则化 |
| P5 | 年休假折算与冲抵口径混乱 | 未休按 300% 全额另付（未扣已付 100%） | 300% 含正常工资 → 实际另付 200% 的冲抵口径显式实现，21.75 天口径参数化 |
| P6 | 二倍工资起算/上限不清 | 从入职当日算、超过 11 个月仍计 | 起算（用工满 1 个月次日）+ 上限（11 个月）+ 已付冲抵规则化，输出逐月明细 |
| P7 | 社平工资/最低工资逐年逐地变 | 硬编码 2024 数值算 2026 年 | `地区 × 年度` 参数包，切换即换参数，跨地区/跨年度混用报错 |
| P8 | 结论无法溯源 | 只给数字，说不出依据 | 每个数值旁挂「法条条款 + 参数来源（哪年哪地社平工资）」 |
| P9 | 参数来源不明仍被采用 | 随手填一个"社平工资" | `status` 门控：`pending` 条目不得进入计算路径（引擎入口单点拒绝） |
| P10 | 结果被当成法律意见 | 用户拿测算当裁决 | 免责声明强制出现在 CLI 输出、报告、GUI、README |

## 二、功能需求（FR 清单，带优先级）

> 优先级：P0 = M0–M2 必做（骨架 + 参数库 + 经济补偿引擎）；P1 = M3 必做（其余三引擎）；P2 = M4–M6（基准/桌面/发布）。

### FR-1 参数库与坐标（P0）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-1.1 | 参数包以 `地区（省/市）× 年度` 为坐标存储 | 每份规则包含 `region_code` / `year` / `status` |
| FR-1.2 | 每份规则包含社平工资（三倍封顶基数）、最低工资、法定节假日日历、口径调整 | schema 校验通过（`lcc.params.validate`） |
| FR-1.3 | 每条参数挂来源（发布机关 + 发布年度 + 口径 + URL + 抓取日期）与 `status` | `validate` 拒绝缺来源的 `verified` 条目 |
| FR-1.4 | **跨地区 / 跨年度混用报错** | 请求 `(region, year)` 与参数包坐标不一致 → 抛出 `ParamCoordinateError` |
| FR-1.5 | 社平工资口径逐地区登记（全口径城镇单位就业人员 / 城镇非私营在岗职工） | 口径字段必填，不得缺省 |
| FR-1.6 | `status=pending` 条目不得进入计算路径 | 引擎入口 `effective_ruleset()` 单点门控；CLI 可 `--preview` 预览但不计算 |

### FR-2 经济补偿 / 赔偿金引擎（P0）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-2.1 | 解除情形 → N / N+1 / 2N 口径判定 | 枚举用例 100% 判定正确（含易混边界） |
| FR-2.2 | 工作年限取整（满 6 个月不满 1 年→1 年；不满 6 个月→半个月） | 边界枚举通过（5/6/11/12 个月） |
| FR-2.3 | 月工资口径：解除前 12 个月平均应得工资 | 输入 12 个月工资明细 → 输出平均值（Decimal） |
| FR-2.4 | 月工资下限不低于当地最低工资 | 低于最低工资时按最低工资计（参数驱动） |
| FR-2.5 | 三倍封顶：月工资 > 当地上年度社平工资 × 3 时按三倍计 | 边界：恰好等于 / 高出 0.01 / 低于 0.01 |
| FR-2.6 | 12 年上限：封顶情形下支付年限 ≤ 12 年 | 边界：11.5 / 12 / 12.5 / 13 年 |
| FR-2.7 | 逐项计算过程输出 + 挂《劳动合同法》第 47 条等依据 | 结果对象含 `basis: [条款 id]` |

### FR-3 加班费引擎（P1）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-3.1 | 工时制度区分：标准 / 综合计算 / 不定时 | 不定时 → 不产生工作日/休息日加班费（法定节假日另按当地口径） |
| FR-3.2 | 三档倍数：工作日 150% / 休息日 200% / 法定节假日 300% | 倍率来自法定常数包（非硬编码），条号入库核对 |
| FR-3.3 | 计算基数口径规则化 | 基数口径枚举（合同约定工资 / 正常工作时间工资），参数驱动 |
| FR-3.4 | 法定节假日日历按 `年度 × 地区` 参数化（含调休） | 日历来自规则包；跨年度使用报错 |

### FR-4 未休年休假折算引擎（P1）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-4.1 | 年休假天数按累计工作年限分档 | 分档表来自法定常数包（满 1 年不满 10 年 5 天等） |
| FR-4.2 | 未休折算：日工资 × 300%，其中 100% 已付 → 实际另付 200% | 输出 `已付部分` / `应另付` 两列 |
| FR-4.3 | 当年度折算：已过日历天数 ÷ 365 × 应休天数，取整规则挂依据 | 边界：天数临界、取整方向 |
| FR-4.4 | 日工资 = 月工资 ÷ 21.75 | 21.75 来自法定常数包（人社部令第 1 号第十一条） |

### FR-5 未签书面劳动合同二倍工资引擎（P1）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-5.1 | 起算：用工满 1 个月的次日起 | 边界：第 29/30/31 天 |
| FR-5.2 | 上限：最长 11 个月 | 边界：11 / 12 个月 |
| FR-5.3 | 二倍工资差额口径（已支付部分冲抵） | 输出逐月明细（月份 / 应付 / 已付 / 差额） |
| FR-5.4 | 输出计算区间 + 逐月明细 + 依据 | 区间端点可复核 |

### FR-6 报告与依据联动（P1）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-6.1 | 一键导出测算说明（Markdown + XLSX） | 两格式内容一致，含输入事实/适用法条/逐项过程/参数来源/结论 |
| FR-6.2 | 每个数值可回溯「法条条款 → 参数来源」 | 报告含参数来源块（哪年哪地社平工资 + 发布机关 + URL） |
| FR-6.3 | 免责声明强制 | CLI / 报告 / GUI / README 四处均出现 |

### FR-7 内置评测基准（P0 起，P2 完善）

| 编号 | 需求 | 验收点 |
|---|---|---|
| FR-7.1 | 口径判定基准：解除情形 → N/N+1/2N 枚举（含易混边界） | 判定准确率 100% |
| FR-7.2 | 封顶与取整边界基准：三倍恰好等于/上下、6 个月临界、12 年上限 | 全通过 |
| FR-7.3 | 参数库自洽基准：跨地区/跨年度一致性 + 非法组合拦截 | 拦截率 100% |
| FR-7.4 | 合成雇佣档案（固定种子，零 API 依赖可复现） | 两次生成逐字节一致；真值与档案同入库 |
| FR-7.5 | 指标写入 README | README 评测表数值与基准实跑一致 |

## 三、非功能需求（NFR）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | **全本地、零上传** | 无任何网络调用；无 LLM 依赖（见决策记录 D-06） |
| NFR-2 | **确定性可复现** | 核心层零第三方依赖；固定种子生成器；冻结产物逐字节一致（LF 行尾 + zip 容器收口） |
| NFR-3 | **Decimal 全链路计价** | JSON `parse_float=Decimal`，引擎全程 Decimal，呈现 `ROUND_HALF_UP` 两位小数；禁 float 尾差 |
| NFR-4 | **零政策字面量** | 全部法定数值（倍率/天数/天数分档/21.75/11 个月）只能来自数据包；对引擎/基准/前端源码做 token 扫描门禁 |
| NFR-5 | **未核对不生效** | `status` 门控单点；参数缺来源不得 `verified` |
| NFR-6 | **可移植** | Python ≥ 3.8；Windows / Linux 双平台 CI |
| NFR-7 | **可测试** | 全量 pytest 离线可跑；CI 多矩阵；干净环境按 README 一次跑通 |
| NFR-8 | **编码安全** | 入口 `_ensure_utf8_stdio()`；非 ASCII 输出不因 cp1252 崩溃 |
| NFR-9 | **合规红线** | 免责声明强制；不使用真实劳动者数据；不提供法律意见/仲裁代理 |

## 四、边界与非目标（守卫清单）

**首期做**：经济补偿/赔偿金、加班费、未休年休假折算、未签劳动合同二倍工资 + `地区 × 年度` 参数库 + 报告导出 + 基准 + 桌面/CLI 双形态。

**首期不做（留扩展，代码预留接口但不出实现）**：

| 不做项 | 原因 |
|---|---|
| 工伤赔偿 | 计算口径随地方工伤目录高度碎片化，缺乏全国统一确定性真值 |
| 社保 / 公积金补缴计算 | 各地社保政策差异大、涉及历史补缴利息，规则复杂且易过期 |
| 竞业限制补偿 | 口径争议大（约定优先/法定比例各地不一），缺乏确定性真值 |
| 股权激励 | 非标准劳动关系标的，估值口径不属劳动法计算范畴 |
| 最低工资查询器 | 纯查询无计算深度 → 并入参数库即可 |
| 劳动仲裁申请书代写 | 出界（法律服务）；仅提供测算参考 |
| 对接仲裁/法院系统 | 无公开接口且涉敏感数据 |

**红线**：
1. 不出具法律意见；正式结论以劳动仲裁/法院裁判为准（免责声明强制）。
2. 参数包未挂来源核对（`status=pending`）不得进入计算路径。
3. 不得使用真实劳动者薪资/身份数据；合成档案一律虚构。
4. 全本地计算存储、零上传。
5. 不复制系列其他项目代码；文档不提及系列其他项目的业务领域（品牌隔离）。
