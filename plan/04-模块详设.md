## 一、数据 schema

### 1.1 地区主数据 `data/regions/regions.json`

```jsonc
{
  "schema_version": 1,
  "regions": [
    {
      "code": "310000",            // 行政区划码（省/直辖市 6 位）
      "name": "上海市",
      "level": "province",
      "parent": null,
      "avg_wage_caliber": "full_caliber_urban_employees",  // 口径枚举
      "caliber_note": "全口径城镇单位就业人员平均工资",
      "status": "pending"          // 地区主数据本身也需核对
    }
  ]
}
```

**口径枚举**（`avg_wage_caliber`）：`full_caliber_urban_employees`（全口径城镇单位就业人员平均工资）、`urban_non_private_on_post`（城镇非私营在岗职工平均工资）、`other`（需 `caliber_note` 说明）。
**理由**：多地已由非私营在岗口径过渡为全口径口径，且**是否用于劳动合同法第 47 条封顶各地口径不一** → 必须逐地区登记，禁止跨地区套用（题目 §五 口径警示）。

```jsonc
        "retrieved_at": null

    },
    "min_wage_monthly": {
```

**坐标规则（FR-1.4）**：文件名中的 `<region>-<year>` 必须与内部 `region_code` / `year` 字段一致，否则 `validate` 报错；`load_ruleset(region_code, year)` 只按精确坐标命中，不做模糊/回退匹配 → 跨地区/跨年度混用在机制上不可能。

## 二、输入事实模型 `lcc/model.py`

```python
@dataclass(frozen=True)
class EmploymentFacts:
    region_code: str            # 坐标
    year: int                   # 计算年度（决定参数包与节假日日历）
    hire_date: date
    terminate_date: date | None
    monthly_wages: tuple[Decimal, ...]   # 解除前 12 个月应得工资（不足则按实际）
    work_system: str            # standard | comprehensive | irregular
    cumulative_service_years: Decimal    # 累计工作年限（年休假分档用，社会累计）
    contract_signed: bool
    contract_signed_date: date | None

@dataclass(frozen=True)
class TerminationFacts:
    ground: str                 # 解除情形枚举（见 §3.1）
```

## 三、经济补偿 / 赔偿金引擎 `lcc/engine/severance.py`

### 3.1 口径判定（FR-2.1）

| 解除情形 `ground` | 说明 | 口径 |
|---|---|---|
| `mutual_agreement` | 协商一致解除（第 36 条） | N |
| `employee_fault_dismissal` | 劳动者过错解除（第 39 条） | 0（无需支付） |
| `employer_unilateral_no_fault` + 已提前 30 日通知 | 第 40 条情形 | N |
| `employer_unilateral_no_fault` + 未提前 30 日通知 | 第 40 条情形 | N+1（代通知金） |
| `economic_layoff` | 经济性裁员（第 41 条） | N |
| `illegal_termination` | 违法解除（第 48/87 条） | 2N |
| `contract_expiry_employer_no_renewal` | 固定期限合同到期不续订（第 46 条第 5 项） | N |
| `employee_resignation_art38` | 劳动者因用人单位违法被迫解除（第 38 条） | N |
| `employee_resignation_voluntary` | 劳动者主动辞职 | 0 |

判定输出：`{ground, formula: "N"|"N+1"|"2N"|"none", basis: [条款 id], reason}`。
**易混边界（进基准枚举）**：第 40 条未提前通知 → N+1 而非 2N；第 39 条过错解除 → 0 而非 N；第 38 条被迫解除 → N（不是 0）。

### 3.2 工作年限取整（FR-2.2）

```
service_months = 完整月数(hire_date → terminate_date) + 余日折算
若 余日 < 15 天 → 不计月；否则 +0.5 月（口径挂条款依据，进基准）
full_years = service_months // 12
rem_months = service_months % 12
若 rem_months >= full_year_threshold_months(6) → 年限 = full_years + 1
否则 → 年限 = full_years + 0.5（不满 6 个月按半个月）
```
输出 `service_years_for_compensation`（可含 .5），并挂 `LCL-47` 依据。

### 3.3 月工资口径（FR-2.3 / FR-2.4）

```
monthly_wage = mean(monthly_wages)          # 解除前 12 个月平均应得工资
若 monthly_wage < min_wage_monthly → monthly_wage = min_wage_monthly   # 下限（参数驱动）
```

### 3.4 三倍封顶与 12 年上限（FR-2.5 / FR-2.6）

```
cap_base = social_avg_wage_monthly × cap_multiple_of_social_avg        # 参数驱动，非硬编码
if monthly_wage > cap_base:
    base_for_calc = cap_base
    years_capped = min(service_years, cap_years)                        # 仅封顶情形受 12 年限制
else:
    base_for_calc = monthly_wage
    years_capped = service_years
```

### 3.5 金额

```
N  = base_for_calc × years_capped
N+1 = N + 代通知金   ← 代通知金 = 劳动者上一个月的工资标准（不适用封顶与最低工资下限）
2N = 2 × N
```
> **代通知金口径（R-01 已闭环，见 plan/06 D-30）**：依《劳动合同法实施条例》第二十条，代通知金按**劳动者上一个月的工资标准**确定（即 `monthly_wages` 序列的**最后一项**，非 12 个月平均），且**不受**第 47 条三倍封顶约束、**不适用**最低工资下限（下限的原文语境是经济补偿的月工资）。此口径与「解除前 12 个月平均工资」**不同**，进基准枚举。
> **月工资口径（D-32）**：`monthly_wages` 约定为「应得工资、剔除加班工资」，同时满足第 47 条（应得工资）与实施办法第十一条（剔除加班工资）两处口径。
> **年限余日折算（D-34）**：完整月数 + 余日（≥15 天计 0.5 月，否则不计），属既定计算口径（非条文），报告显式标注。

输出结构：`{formula, monthly_wage_avg, last_month_wage, min_wage_applied, cap_applied, cap_base, years_used, years_capped, amount, steps: [...], basis: [...]}`。

## 四、加班费引擎 `lcc/engine/overtime.py`

### 4.1 工时制度门控（FR-3.1）

| `work_system` | 工作日延长 | 休息日 | 法定节假日 |
|---|---|---|---|
| `standard` | 150% | 200%（不能补休时） | 300% |
| `comprehensive` | 超出周期总工时的部分按 150%；法定节假日仍 300% | 同左 | 300% |
| `irregular` | 不适用 | 不适用 | 按当地口径（多地仍需支付） |

> **v1 实现口径（R-03 已闭环，见 plan/06 D-41）**：上表为**法律说明**。v1 引擎的
> 倍率**一律由日历日期类型**（`ruleset.holiday_day_type` 四类）+ 常数包
> `overtime.rates.*` 决定，**不随 `work_system` 变化**——依据《劳动法》第四十四条
> 按「延长工时 / 休息日 / 法定休假日」三种情形分档，与工时制度无关。`work_system`
> 在 v1 为**记录性字段**（入报告留痕）；不定时工作制的地区性例外无全国统一口径，
> 若后续确认某地区确需差异，**逐地区登记到规则包**（不硬编码）。

### 4.2 计算基数口径（FR-3.3）

```
base = 劳动者月工资（12 个月平均应得工资，剔除加班工资；见 D-33）
若 base < min_wage_monthly → base = min_wage_monthly
hourly = base ÷ (monthly_pay_days(21.75) × standard_daily_hours(8))   ← 两值均来自常数包
```

> **基数口径（D-33）**：M1 真值语义取劳动者本人月工资（事实驱动，地区无关）。规则包级 `overtime_base_caliber`（合同约定工资 / 正常工作时间工资）与不定时工作制口径差异并入 **R-03**，M3 前若确认地区差异再参数化。
> **日工时口径**：`standard_daily_hours` 来自常数包（依据《劳动法》第三十六条「每日工作时间不超过八小时」），与 `monthly_pay_days`（21.75，实施办法第十一条）同属常数包，**不得内联**。

### 4.3 金额

```
for each entry in overtime:
    day_type = ruleset.holiday_day_type(entry.date)   # 日历唯一来源，四类
    # statutory_holiday → 300%；rest_day / adjusted_workday 未补休 → 200%；
    # 其余（workday）→ 150%；显式 kind 覆盖 auto
    rate = overtime_rate(day_type 对应档)
    amount += hourly × entry.hours × rate
```

日历四类（均来自该年度该地区参数包，跨年度使用报错）：
| `holiday_calendar` 字段 | 日期类型 | 未补休时倍率 |
|---|---|---|
| `days` | `statutory_holiday` 法定节假日 | 300% |
| `rest_days` | `rest_day` 调休/连休休息日（非法定） | 200% |
| `adjusted_workdays` | `adjusted_workday` 调休上班日 | 200% |
| （其余） | `workday` 正常工作日 | 150% |

> **为何需要 `rest_days`**：放假安排里「放假调休 8 天」中的非法定节假日（如春节连休的 2/1–2/4）仍是**休息日**，未补休时按 200% 而非 150%。若只登记 `days` + `adjusted_workdays`，这些日期会退化成工作日口径 → 系统性少算。日期类型判定收在 `ruleset.holiday_day_type()` 单点（与 `gate` 同纪律），引擎不得自建日历逻辑。

输出逐条明细 + 合计 + `basis: ["LL-44"]`。

## 五、未休年休假折算引擎 `lcc/engine/annual_leave.py`

### 5.1 应休天数（FR-4.1）

```
按 cumulative_service_years 落入 entitlement_tiers → 年度应休天数 entitlement_days
```

### 5.2 当年度折算（FR-4.3）

```
elapsed_days = (terminate_date - year_start).days + 1     # 当年度已过日历天数
prorated = elapsed_days ÷ days_per_year(365) × entitlement_days   # 折算应休天数（保留原值）
```

### 5.3 未休折算与冲抵（FR-4.2 / FR-4.4）

```
daily_wage = monthly_wage ÷ monthly_pay_days(21.75)
unused_raw  = prorated - annual_leave_taken_days
unused_days = max(0, floor(unused_raw))     # R-02 已闭环（plan/06 D-31）：不足 1 整天不计
payable_total = daily_wage × unused_days × unused_multiple(300%)
already_paid   = daily_wage × unused_days × already_paid_portion(100%)
additional_due = payable_total - already_paid        # 实际另付 200%
```
> **取整口径（R-02 已闭环，见 plan/06 D-31）**：依《实施办法》第十二条「折算后不足 1 整天的部分不支付未休年休假工资报酬」——取整方向为**向下取整**，且作用于**扣除当年度已安排天数之后的应休未休天数**（`prorated` 本身保留原值供报告展示）。此为基准枚举点。

输出 `{entitlement_days, prorated_days, taken_days, unused_days, daily_wage, payable_total, already_paid, additional_due, basis}`。

## 七、门控与依据联动

### 7.1 status 门控（FR-1.6）

```python
def effective_ruleset(ruleset, *, allow_pending=False) -> EffectiveRuleset:
    """唯一能产出可计算规则集的入口。pending 条目 → GateError。"""
```
- 逐条检查 `params.*.status` 与 `constants.*.status`；
- 任一 `pending` → `GateError`（列出条目路径），除非 `allow_pending=True`（仅 `--preview` 用，且**不得输出金额**）；
- 引擎签名只接受 `EffectiveRuleset`，不接受裸 dict → 类型层面杜绝绕过。

### 7.2 依据联动（FR-6.2）

每个引擎结果含 `basis: list[clause_id]`；`pipeline` 汇总后由 `law.resolve(ids)` 取条款详情；`LawBasisError`（exit 1）在条款 id 不存在时抛出 → 防止结论挂空依据。
