## 一、分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ 表现层  GUI (PySide6, code/src/lcc/gui/)  │  CLI (lcc.cli)   │   ← 只消费引擎 API
├─────────────────────────────────────────────────────────────┤
│ 编排层  lcc.pipeline  (CalcRequest → CalcResult, 零 Qt)      │   ← CLI/GUI 共用单一编排
├─────────────────────────────────────────────────────────────┤
│ 引擎层  lcc.engine.severance / overtime / annual_leave /     │
│         double_wage            (纯函数, Decimal, 零 IO)      │
├─────────────────────────────────────────────────────────────┤
│ 规则层  lcc.params (参数库)   lcc.law (条款库)   lcc.gate    │   ← status 门控单点
├─────────────────────────────────────────────────────────────┤
│ 数据层  data/rules/*.json   data/law/*.json   data/regions/  │   ← 冻结产物, 禁手改
└─────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**：表现层 → 编排层 → 引擎层 → 规则层 → 数据层。引擎层不得 import CLI/GUI（AST 守门测试断言）。

## 二、技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Python ≥ 3.8 | 本机 3.8.8 与 3.12.10 双版本实测；CI 双版本矩阵 |
| 核心层依赖 | **零第三方** | 全本地可复现、打包体积小、干净环境无解析风险 |
| 计价类型 | `decimal.Decimal` | 金额边界要检出 1 分差异，float 尾差不可接受（NFR-3） |
| 数据格式 | JSON（`parse_float=Decimal`） | 人可读、可 diff、可挂 status 与来源 |
| 规则包生成 | `tools/gen_rulesets.py`（自制确定性 RNG） | 冻结产物，禁手改；再生成逐字节一致 |
| CLI | `argparse`（stdlib） | 零依赖；退出码语义锁进测试 |
| GUI | PySide6（optional extra `gui`） | 系列惯例；惰性导入，缺依赖给安装提示 |
| 报告导出 | Markdown（stdlib）+ XLSX（openpyxl，optional extra `report`） | 报告是交付物；XLSX 是 HR 实际工作格式 |
| 打包 | PyInstaller（optional extra `build`） | onedir 双 exe；与 CLI 同一 main |
| 测试 | pytest | 本机已有；离线可跑 |
| CI | GitHub Actions（windows×3.8/3.12 + ubuntu×3.12） | 老解释器只在 windows 守（见 06 决策） |

```

│   │   ├── _stdio.py         UTF-8 入口守卫

│   │   ├── law.py            条款库加载
│   │   ├── model.py          输入事实（EmploymentFacts / TerminationFacts）
│   │   ├── pipeline.py       编排（CalcRequest/CalcResult）
│   │   ├── engine/
│   │   │   ├── severance.py
│   │   │   ├── overtime.py
│   │   │   ├── annual_leave.py
│   │   │   └── double_wage.py
│   │   ├── report/           Markdown / XLSX 导出
│   │   ├── cli.py            argparse 入口
│   │   └── gui/              PySide6（惰性导入）
```

**仓库根 vs 包根**：仓库根 = 项目根；Python 包在 `code/src/lcc`，`pyproject.toml` 在 `code/`。CLI 从仓库根跑用 `python -m` 需 `PYTHONPATH=code/src`，README 给可复制命令（干净环境验证的依据）。

## 四、数据流（一次计算）

```
用户输入事实 (JSON / GUI 表单)
   ↓ model.EmploymentFacts / TerminationFacts  (校验 + Decimal 化)
params.load_ruleset(region_code, year)          (坐标校验：跨地区/年度报错)
   ↓
gate.effective_ruleset(ruleset)                 (status 门控：pending 条目 → 拒绝)
   ↓
engine.<模块>.compute(facts, ruleset, constants) (纯函数, 返回带 basis 的结果)
   ↓
pipeline.compute_full_calc(CalcRequest) → CalcResult
   ↓
report.render_markdown / render_xlsx            (含免责声明 + 参数来源块)
   ↓
CLI stdout / 文件 | GUI 页签渲染
```

## 五、关键技术决策（详见 [06-决策记录.md](06-决策记录.md)）

1. **零 LLM**：纯确定性规则 + 结构化输入，无解析兜底需求 → 全链路零 API 依赖（NFR-1/NFR-2）。
2. **Decimal 全链路**：金额与天数统一 Decimal，量化口径 `ROUND_HALF_UP` 两位小数（金额）/ 天数按条款口径取整。
3. **参数包 = 冻结产物**：`tools/gen_rulesets.py` 生成，禁手改，配「再生成逐字节一致」守门测试。
4. **status 门控单点**：只有 `gate.effective_ruleset()` 能产出"可计算规则集"，引擎不接受裸 dict。
5. **零政策字面量门禁**：法定数值收编为禁用 token，扫描引擎/基准/前端源码（含 docstring/注释）。
6. **编排上收**：`pipeline` 是唯一编排源，CLI 与 GUI 共用；GUI 零判定逻辑。
7. **确定性落盘**：文本用 `write_bytes` / `newline="\n"`；未来若产出 xlsx/docx 冻结件，zip 容器统一 `ZIP_STORED` + `create_system=0` + 固定时间戳。

## 六、错误与退出码

| 异常 | 触发 | CLI 退出码 |
|---|---|---|
| `InputError` | 输入 JSON 缺失/格式错/字段非法 | 2 |
| `ParamCoordinateError` | 请求的地区/年度无对应参数包，或跨坐标混用 | 2 |
| `GateError` | 命中的参数条目 `status=pending`（未核对） | 2 |
| `LawBasisError` | 结论引用的条款 id 在条款库中不存在 | 1 |
| `ComputationError` | 计算过程中的非法状态（如负工资、日期区间倒置） | 1 |
| 成功 | — | 0 |

**降级语义**：`--preview` 允许在门控命中时打印参数预览但**不输出任何金额结论**，退出码 1。
退出码表锁进 `code/tests/test_cli_exit_codes.py`，后续重构不得漂移。
