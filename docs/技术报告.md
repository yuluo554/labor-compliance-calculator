> 版本：v1（2026-10-13）｜对应里程碑 **M5 桌面交付**
> 仓库：`yuluo554/labor-compliance-calculator`｜许可：MIT

## 一、问题与定位

劳动用工解除时的金额测算，难点不在公式本身，而在**口径**：

1. **口径判定**——同一份事实，解除情形不同则结论在 `N` / `N+1` / `2N` / 不支付之间跳变
   （第 39 条过错解除不支付，第 40 条未提前通知要加代通知金，第 38 条被迫解除要支付）；
2. **参数漂移**——社平工资、最低工资、法定节假日日历逐地逐年发布，
   且社平工资口径多地已由「城镇非私营在岗职工平均工资」过渡为「全口径城镇单位就业人员平均工资」，
   是否用于第 47 条封顶各地不一；
3. **不可追溯**——聊天式问答给出的数字没有参数来源、没有法条依据、没有边界枚举，
   错了也无从复核。

本项目的定位是把这三件事做成**机制**：口径判定规则化、参数版本化且强制挂来源、
每个结论旁挂法条条款与参数出处。**全本地、零上传、零 LLM**——所有结论由确定性规则产生。

### 1.1 交付形态

| 形态 | 入口 | 说明 |
|---|---|---|
| 桌面应用 | `lcc-gui.exe`（PyInstaller onedir） | PySide6 多页签，四类计算 + 参数库 + 报告 + 依据 |
| 命令行 | `lcc-cli/lcc.exe`、`python -m lcc` | `params` / `doctor` / `calc` / `report` 子命令 |
| 库 | `import lcc` | 核心层零第三方依赖，可嵌入 |

## 二、架构

### 2.1 分层

```
表现层   gui/ (PySide6)          cli.py (argparse)      report/ (Markdown/XLSX)
   │            └──────────────┬──────────────┘
编排层   lcc.pipeline  (CalcRequest → CalcResult，零 Qt、零 IO 副作用)
   │
引擎层   engine.severance / overtime / annual_leave / double_wage  (纯函数, Decimal, 零 IO)
   │
规则层   params (参数库)   law (条款库)   gate (status 门控单点)
   │
数据层   data/rules/*.json   data/law/*.json   data/constants/*.json   data/regions/*.json
```

**依赖方向单向向下**，由三条可执行断言守门（`code/tests/test_repo_gates.py`）：

- 引擎/规则层不得 import CLI/GUI；
- 核心层（引擎/规则/编排/Markdown 报告）**零第三方依赖**，只有 stdlib 与 lcc 内部；
- 表现层的可选依赖（PySide6 / openpyxl）必须是「函数内 + `try/except ImportError`」的守卫式惰性导入。

> **为什么 `report/xlsx.py` 单独成文件**：它是报告侧唯一的可选依赖边界。
> 拆开后 `report/__init__.py` 保持 stdlib-only，于是「Markdown 导出」这条通路
> 在没有任何第三方依赖的机器上始终可用。

### 2.2 三条贯穿性纪律

**（1）status 门控单点。** `gate.effective_ruleset()` 是**唯一**能产出「可计算规则集」
的入口；引擎签名只接受 `EffectiveRuleset`，不接受裸 `dict`。`pending`（未核对）条目
一旦进入计算路径即抛 `GateError`（exit 2）。这是「未挂官方原文核对就不得参与计算」
在类型层面的落实——不靠自觉，靠签名。

**（2）零政策字面量。** 全部法定数值（倍率、天数分档、口径天数、上限年限/月数）
只能来自 `data/constants/` 与 `data/rules/`。`tools/check_no_literals.py` 扫描
引擎/基准/前端源码（**含 docstring 与注释**），命中禁用 token 即门禁失败。
禁用面含 `21.75`、`365`、`150/200/300`（及其百分号形态）、`1.5/2.0/3.0`。

**（3）真实来源可溯源。** 每条 `verified` 条目的 schema 校验强制要求
`publisher` / `published_year` / `url` / `retrieved_at` 齐备，常数条目另需 `basis`（条款 id）
与 `source.channel`。缺任一字段即 `ParamSchemaError`。

### 2.3 Decimal 全链路

金额与天数的每个环节都用 `decimal.Decimal`：JSON 以 `parse_float=Decimal` 读入，
金额量化两位 `ROUND_HALF_UP`。基准里的边界断言一律在 `±0.01`（金额精度量级）邻域做，
确保 1 分的差异能被检出——float 尾差在这个尺度上不可接受。

## 三、口径判定规则化

### 3.1 解除情形 → 口径

`engine/severance.py` 的 `FORMULA_BY_GROUND` 是**纯映射表**（无数值）：

| 解除情形 | 条款 | 口径 |
|---|---|---|
| 协商一致解除 | 第 36 条 | N |
| 劳动者过错解除 | 第 39 条 | none（不支付） |
| 无过失性辞退（未提前 30 日通知） | 第 40 条 | **N+1**（代通知金） |
| 无过失性辞退（已提前通知） | 第 40 条 | N |
| 经济性裁员 | 第 41 条 | N |
| 违法解除 | 第 48/87 条 | **2N** |
| 合同到期用人单位不续订 | 第 46 条第 5 项 | N |
| 劳动者被迫解除 | 第 38 条 | N |
| 劳动者主动辞职 | — | none（不支付） |

**易混边界**（进基准 B1 枚举）：第 40 条未提前通知是 **N+1 而非 2N**；
第 39 条过错解除是 **none 而非 N**；第 38 条被迫解除是 **N 而非 0**。

### 3.2 三个需要显式定夺的口径（均已闭环）

- **代通知金基数（R-01 → D-30）**：按《劳动合同法实施条例》第二十条取
  **劳动者上一个月工资标准**，与「解除前 12 个月平均」**不同**，且不受三倍封顶与
  最低工资下限约束（下限原文语境是经济补偿的月工资）。
- **年休假折算取整（R-02 → D-31）**：依《实施办法》第十二条，**向下取整（不足 1 整天不计）**，
  且作用于**扣除当年度已安排天数之后的应休未休天数**（`floor(折算应休天数 − 已安排天数)`，
  下限截 0）；折算应休天数本身保留原值供报告展示。
- **不定时工作制的法定节假日加班费（R-03 → D-41）**：查证后**不新增全国统一参数**。
  倍率的全国统一依据是《劳动法》第四十四条，按「延长工时 / 休息日 / 法定休假日」三情形分档，
  **与工时制度无关**；地区性例外无全国统一口径，强行内联会制造「第二份真相」。
  故 v1 中 `work_system` 是**记录性字段**，倍率一律由日历日期类型 + 常数包决定。

### 3.3 年限与封顶

- **年限取整**：完整月数 + 余日（余日 ≥ 15 天计 0.5 月，D-34，属既定计算口径而非条文）；
  满 6 个月不满 1 年按 1 年，不满 6 个月按半个月（第 47 条）。
- **三倍封顶**：月工资 **严格大于** 社平工资 × 倍数才封顶（恰好等于不封顶）；
  封顶时年限 ≤ 12 年。

## 四、参数库版本化

### 4.1 一文件一坐标

`data/rules/ruleset-<region>-<year>.json`——文件名与内部 `region_code`/`year` **强一致校验**。
`load_ruleset()` 只做精确坐标命中，**不做模糊或年度回退**；跨坐标混用在机制上不可能发生。

```
data/rules/ruleset-110000-2025.json   北京市 × 2025（verified）
data/rules/ruleset-110000-2026.json   北京市 × 2026（verified）
data/rules/ruleset-310000-2025.json   上海市 × 2025（verified）
data/rules/ruleset-310000-2026.json   上海市 × 2026（verified）
data/rules/ruleset-440000-*.json      广东省（pending，演示门控拦截）
data/rules/ruleset-320000-*.json      江苏省（pending，演示门控拦截）
```

试点选择（R-04 → D-35）：北京 + 上海 × 2025/2026，共 4 个坐标全部 `verified`；
广东/江苏留骨架 `pending`，用来**证明「未核对即拒绝计算」机制有效**——这不是遗漏，
是可被验证的负例。

### 4.2 参数来源登记

每份规则包的每个条目挂 `source`（发布机关 + 发布年度 + 文号 + URL + 抓取日期），
社平工资额外登记 `caliber`（口径）与 `basis_year`（数值所属年度）。
报告与 GUI 的「参数来源块」直接渲染这些字段——**每个数值都能回到它的官方出处**。

### 4.3 冻结产物

`data/rules/*` 与 `data/truth/*` 均由生成器（`tools/gen_rulesets.py` / `tools/gen_cases.py`）
产出，**禁手改**；配「再生成逐字节一致」守门（`--check` 模式），CI 每次跑。

## 五、日历唯一来源

法定节假日日历的日期类型判定**只在** `Ruleset.holiday_day_type()` 一处，分四类：

| 类型 | 含义 | 加班倍率档位（常数包键） |
|---|---|---|
| `statutory_holiday` | 法定节假日 | `overtime.rates.statutory_holiday`（最高档） |
| `rest_day` | 调休休息日（放假但非法定节假日） | `overtime.rates.rest_day_no_compensatory`（次档） |
| `adjusted_workday` | 调休上班日（原休息日改为工作日） | 同上（法律性质仍是「休息日工作」） |
| `workday` | 其余 | `overtime.rates.workday_extension`（最低档） |

**D-37 修正的实际影响**：早期 `holiday_calendar` 只有 `days` + `adjusted_workdays` 两字段，
导致放假安排中「放假调休 N 天」的非法定节假日退化成工作日（150%）→ **系统性少算**。
补入 `rest_days` 后按休息日口径（200%）计，并由基准覆盖四类联动。

引擎**不得自建日历逻辑**——否则政策语义会出现第二份实现。

## 六、基准体系

`tools/bench.py`——全离线、单次全量 < 1 秒，退出码三语义（0 达标 / 1 未达标 / 2 用法错误）。
M5 实测：

| 基准 | 内容 | 结果 |
|---|---|---|
| B1 口径判定 | 解除情形 → N/N+1/2N/none 枚举（含易混边界） | 9/9 = 100% |
| B2 边界与全模块对账 | 真值库 406 条经**四引擎**重算，逐字段 + 隐含结论对账 | 406/406 |
| B3 参数库自洽 | 不存在坐标 / 年度回退 / 跨坐标混用 / pending 条目拦截 | 5/5 = 100% |
| B4 参数推导边界扫描 | **不依赖真值库样本**：切换端点全由规则表/常数包推出，±0.01 邻域断言 | 96/96 |
| B5 双向对账 | 公式推导端点 vs 穷举扫描恢复切换点，两条独立路径互验 | 40/40 |
| 阳性对照 | 已核对坐标必须放行（防「拦截率 100%」是「什么都拦」的空验） | 4/4 |

### 6.1 两条独立实现路径

真值的**单一实现源**在 `benchmark/cases.py`（M1 冻结产物），四引擎是**独立于它的第二实现**，
两者逐字段一致才通过。这条纪律的表述是「**不许改真值凑引擎**」：发现口径错误要改引擎 + 加测试。

M2 期出现过一个例外并留下了决策（D-39）：检查器**谓词自身不自洽**（`n_plus_1_uses_last_month_wage`
原实现与真值自身 `amount` 矛盾，会误判「上月工资恰好等于封顶基数」的合法巧合）。
此时改**谓词**（不动冻结产物），`--check` 仍 `FROZEN_TRUTH_OK`。
判据是「冻结产物是否变化」，而非「有没有改检查代码」。

而当真值语义**本身口径错误**时，须**引擎与真值同源修正**（D-42：年休假「累计不满 1 年 →
应休 0 天」）。两种情况都以 `gen_cases.py --check` 仍 `FROZEN_TRUTH_OK` 为判据。

### 6.2 两种基准驱动方式的分工

- **B2 是样本驱动**：真值库记录重算对账。它只能覆盖真值库恰好包含的样本。
- **B4/B5 是规则驱动**：端点由规则表/常数包**推导**，不读真值库。
  B4 验「端点应当在哪」，B5 验「引擎实际行为在端点处与参数语义吻合」。
  测试内含 `test_b4_does_not_read_truth_library`——临时清空真值库后 B4/B5 仍须全通过。

### 6.3 非空验（防「跑通但抓不住漂移」）

基准全绿本身可能是空验。故测试内**注入语义漂移**并断言基准**必须报失败**：

- `test_b4_detects_cap_switch_drift`：封顶比较 `>` → `>=` → B4 必须 FAIL；
- `test_b5_detects_year_rounding_drift`：年限阈值 `>=` → `>` → B5 必须 FAIL。

实测对引擎源码注入 4 类漂移（封顶 `>=`、年限阈值 `>`、年休假分档下界 `>`、二倍工资首月 −1），
B4 与 B5 **全部捕获**（每条至少一侧 FAIL）。

## 七、桌面交付

### 7.1 编排上收：GUI 与 CLI 共用一条通路

`lcc.pipeline` 是唯一编排源（D-13）。表现层只经它的公开入口行事：

```
build_case(raw)          → 输入校验（表现层不 import lcc.model）
build_request(case, ...) → 构造请求（默认模块集合只有一处定义）
compute_full_calc(req)   → 计算
parameter_overview()     → 参数库概览
clause_overview()        → 条款库概览
diagnostics()            → 环境自检（CLI doctor 的数据源）
```

**「GUI 层零判定逻辑」不是口头承诺**，而是 `code/tests/test_gui_layer.py` 的三条 AST 断言：

1. GUI 不 import 引擎/参数库/门控/条款库/模型（只允许 `lcc.pipeline` / `lcc.errors` / `lcc.report`）；
2. GUI 不含数值算术运算（`BinOp` 且两侧操作数均非字符串字面量的 `*` `/` `-` `//` `%` `**`）；
3. GUI 不含政策数值字面量（`21.75` / `365` / `150` / `200` / `300` / `1.5` / `2.0` / `3.0`）。

另有 `test_pipeline_orchestration.py` 验证**行为一致性**：CLI stdout 打印的金额
= pipeline 直调结果的对应字段 = 报告章节里的金额；且同一输入两次调用逐字段一致（无隐藏状态）。

> 这条纪律落实时立刻产生了可见收益：GUI 起初 import 了 `lcc.model` 做输入校验，
> 被 AST 守门拦下后改为 `pipeline.build_case()`，CLI 也一并收口——
> 于是「输入格式解释」在全项目只有一份实现。

### 7.2 报告导出

`report/` 的结构是把 `CalcResult` 摊成**一份章节结构**（`report_sections()`），
Markdown 与 XLSX 都从它渲染。于是 FR-6.1 要求的「两格式内容一致」不是靠人工比对，
而是**结构上不可能不一致**——单一渲染源。

报告必含（均有测试）：

- 输入事实（原样搬运，不解释）；
- **参数来源块**：每个参数挂发布机关 + 年度 + 文号 + URL + 抓取日期；
- 逐项计算过程：直接渲染引擎产出的 `steps` 留痕（报告层不重算）；
- 适用依据：法律名 + 条号 + 要点；
- **免责声明**（FR-6.3）。

XLSX 走 `openpyxl`（optional extra），缺失时抛 `OptionalDependencyError`（exit 1）
并提示回退 Markdown——不崩溃、不静默产出半成品。

**XLSX 的确定性落盘**（D-16 纪律的一次实战）：`openpyxl` 的 `save_workbook()`
会在写盘瞬间把 `docProps/core.xml` 的 `dcterms:modified` **无条件覆盖为当前 UTC 时刻**
（实测 openpyxl 3.1.5 `writer/excel.py`），zip 条目时间戳也取当前时间——于是同一输入
两次导出**字节不同**。因此在保存后增加 `_canonicalize_archive()`：读出全部条目、
把两个时间戳归一化为固定值、以固定时间戳 + `create_system=0` 重打包。
`test_xlsx_export_is_byte_reproducible` 是这次修复的回归守门（无该修复必然失败）。

> 这条纪律不是先验的：文档初稿断言「XLSX 可复现」，实测 sha256 却不同；
> 定位到 openpyxl 的写盘行为后修复，**并把结论改成实测结果**而非保留原断言。

### 7.3 打包

PyInstaller onedir 双 exe（D-19）：

- `tools/lcc-cli.spec` → `dist/lcc-cli/lcc.exe`（`console=True`）
- `tools/lcc-gui.spec` → `dist/lcc-gui/lcc-gui.exe`（`console=False`）

**datas 白名单单一源**：两个 spec 都不内联文件清单，统一调 `lcc.packaging.build_datas()`。
该函数只列**显式数据子目录**（`constants` / `law` / `regions` / `rules` / `truth`），
不做目录通配——确保未入库的官方原文快照目录不会被打进发布物。

> **为什么 `packaging.py` 放在包内而不是 `tools/`**：顶层模块名 `packaging` 会
> **遮蔽 PyPI 的 `packaging`**（PyInstaller 自身依赖它做版本判断），放 `tools/` 需要
> 给 spec 加 `sys.path` 而引发构建期混乱。同时「装到哪」（`build_datas`）与
> 「从哪找」（`data_paths`）本是同一件事的两面，放同一包内便于对齐。

**冻结态数据定位**（`data_paths.py`）覆盖两个世代：
PyInstaller 6.x 的 `sys._MEIPASS/data`，与 5.x 的 `exe目录/_internal/data`。

**验证方式**（`tools/verify_package.py`）：把 onedir 产物复制到临时**中立目录**，
再用**最小环境**（只保留 `SystemRoot` 等系统必需变量，显式剔除 `PYTHONPATH` /
`LCC_DATA_DIR`）跑 CLI 六连 + 报告导出。这一步是必要的——在仓库根跑 exe 会因 `data/` 回溯
命中源码树而「假绿」。

实测（M5 收尾）：

| # | 命令 | 退出码 | 断言 |
|---|---|---|---|
| 1 | `lcc params` | 0 | 输出含「规则包」 |
| 2 | `lcc doctor` | 0 | 输出含「自检结论」 |
| 3 | `lcc calc <sample> --modules severance` | 0 | 输出含「经济补偿」 |
| 4 | `lcc calc <sample>`（默认四模块） | 0 | 输出含四模块标签 |
| 5a | `lcc calc --preview <sample>`（已核对坐标） | 0 | 照常输出金额，**不含**「未核对」 |
| 5b | `lcc calc --preview <pending>`（门控命中） | 1 | 输出含「预览模式」，**不输出金额** |
| 6 | `lcc report <sample> --output *.md` | 0 | 文件存在且含免责声明 |
| 7 | `lcc report <sample> --output *.xlsx` | 0（或 1 + 提示） | 含 openpyxl 时产出文件；未含时**明确提示回退 Markdown**而非崩溃 |

> 报告导出这一步是**必要的**：打包时若解释器未装 `openpyxl`，XLSX 通路会静默降级。
> 验证脚本因此对两种情况都断言——有依赖必须产出文件，无依赖必须给出明确提示（exit 1）。
> 发布构建的解释器须先装 `openpyxl`，否则发布物不具备 README 承诺的 XLSX 能力。

从冻结 exe 导出的 Markdown 与 XLSX 均**逐字节可复现**（两次运行 sha256 一致，
且 XLSX 哈希与源码态构建相同）——说明 `_canonicalize_archive()` 在冻结态同样生效。

GUI exe 以 `QT_QPA_PLATFORM=offscreen` 启动后持续运行至主动终止 → 判通过
（窗口态无 stdout，只能验「能起来且不崩」）。

> **一处实测踩坑**：PyInstaller 5.13.2（本机 3.8 自带）在扫描 PySide6 6.6 字节码时
> 抛 `Instruction object is not iterable`，GUI 打包必须用 PyInstaller ≥ 6。
> 故发布构建用 `py -3.12`（本机 6.22.3）。spec 里对 5.x/6.x 的属性差异用
> `getattr(a, "zipped_data", [])` 兜底，同一份 spec 两个版本都能跑。

### 7.4 演示素材

`tools/make_demo_assets.py` 以 offscreen Qt 渲染 8 张页签截图 + 1 个循环 GIF，
输出到 `docs/demo/`。两点工程处理：

- **字体**：Qt 6 起不再随附字体，offscreen 平台不会自动扫描系统字体目录，
  中文会渲染成豆腐块。脚本按候选路径显式加载 CJK 字体（Windows 优先 Microsoft YaHei）；
- **可复现**：固定帧序、固定窗口尺寸、固定 GIF 时长与调色板，不写入当前时间。
  实测两次独立生成的 9 个文件 **sha256 全部一致**。

## 十、口径速查（改动会打挂基准的约定）

1. **真值语义**：`expected` 主期望 + `also_expect` 隐含结论；语义单一实现源
   `lcc/benchmark/cases.py`。
2. **不许改真值凑引擎**；检查器谓词自身不自洽可改谓词（D-39），真值语义本身口径错
   须引擎与真值同源修正（D-42）。判据均为 `gen_cases.py --check` 仍 `FROZEN_TRUTH_OK`。
3. **Decimal 口径**：JSON `parse_float=Decimal`；金额量化两位 `ROUND_HALF_UP`；
   年休假应休未休天数**向下取整**（D-31）；年限余日 ≥15 天计 0.5 月（D-34）。
4. **status 门控单点**：只有 `gate.effective_ruleset()` 产出可计算规则集。
5. **坐标精确匹配**：`load_ruleset` 不做模糊/回退；跨坐标必须报错。
6. **零政策字面量**：新增引擎/基准/前端代码前先看 `BANNED_TOKENS`。
7. **退出码**：0 成功 / 1 降级或计算非法 / 2 输入、坐标或门控错误。
8. **冻结产物纪律**：生成器产出禁手改；文本 `write_bytes` + `\n`。
9. **日历唯一来源**：日期类型判定只在 `ruleset.holiday_day_type()`（四类）。
10. **月工资口径**（D-32）：`monthly_wages` 为「应得工资、剔除加班工资」，
    单序列同时服务经济补偿/年休假/加班费/二倍工资。
11. **加班基数**（D-33）：劳动者月工资（12 个月平均，不低于最低工资），**地区无关**；
    倍率一律由日历 + 常数包决定，不随 `work_system` 变化（D-41）。
12. **二倍工资区间**：起算 = 用工满一个月的**次日**（月末夹取）；
    硬性截止 = 用工满一年之日；区间月数首尾含当月。
